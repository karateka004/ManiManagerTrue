# 🤖 Промты для Claude Code

Готовые промты для дальнейшего развития приложения. Скопируй один,
вставь в Claude Code в корне проекта, дай ему работать.

> **Совет:** клади свои референсы (скриншоты) в `docs/references/` и
> упоминай их в промтах — Claude посмотрит и подстроится.

---

## 1. Кастомные SVG-иконки в стиле Monefy

```
Сейчас категории в src/store/categories.ts используют эмодзи в поле `emoji`.
Замени это на компонент-иконку (контурный SVG в стиле line-art, stroke-width 1.5,
24x24, currentColor) — по одной на категорию.

Создай src/components/icons/CategoryIcon.tsx, который принимает categoryId
и рендерит соответствующую SVG. Иконки нарисуй сам, ориентируясь на стиль
Monefy / Tabler Icons (тонкие линии, скруглённые концы).

Затем замени все места рендера {c.emoji} на <CategoryIcon id={c.id} />.
Сохрани цвет иконки = c.color через currentColor.
```

## 6. Синхронизация через Supabase

```
Подключи Supabase для синхронизации транзакций между устройствами:

1. Установи @supabase/supabase-js.
2. Создай src/lib/supabase.ts с клиентом (URL и anon key из .env).
3. Используй Telegram initData как auth: отправляй его в edge function,
   которая верифицирует HMAC и возвращает Supabase JWT.
4. Схема таблицы transactions:
   id uuid pk, user_tg_id bigint, type text, amount numeric,
   category_id text, note text, date timestamptz, created_at timestamptz.
5. В store добавь syncPush() и syncPull(), вызывай syncPush() после
   addTransaction/removeTransaction. На старте — syncPull().
6. Не теряй оффлайн-функциональность: если запрос упал — продолжай
   работать локально, retry на следующем экшене.

Подготовь README с инструкцией по созданию проекта в Supabase
и SQL для создания таблицы и RLS-политик.
```

## 7. Регулярные платежи (подписки)

```
Добавь сущность RecurringPayment:
{ id, type, amount, categoryId, note, dayOfMonth, nextRun, active }

В Settings → новая секция "Регулярные платежи" со списком и кнопкой
добавления. UI похожий на AddTransactionSheet, но с дополнительным
полем "день месяца" (1-31).

Логика: при открытии приложения, для каждого активного платежа,
если nextRun < today — добавь transaction в store и обнови nextRun
на следующий месяц. Учитывай месяцы с разным числом дней.
```
